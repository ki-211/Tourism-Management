# 架构说明

## 模块

后端按 `auth`、`activity`、`attendance`、`room`、`location`、`media`、`vehicle`、`common` 划分。Controller 只处理协议和校验，Service 负责事务与权限，Repository 负责持久化。操作者始终来自 JWT，不接受客户端传入的 `userId` 或 `creatorId`。

前端以 `services/api.ts` 统一请求和一次性刷新，以 `services/realtime.ts` 管理 WebSocket。活动空间拆为聊天、签到、相册和位置四个组件；位置共享由全局 Pinia Store 管理，因此切换活动空间标签不会中断共享，地图组件只负责展示成员位置和处理增量事件。

## 数据与一致性

Flyway `V1__baseline.sql` 创建核心业务表，`V2__account_security.sql` 增加令牌版本与账号删除时间。创建活动与负责人自动报名、负责人转让、签到写入均在事务中执行；唯一约束阻止重复报名和重复签到。业务时间统一由可注入的 `Clock` 提供，默认时区为 `Asia/Shanghai`，避免服务器系统时区改变业务判断。

HTTP 是最终事实来源。WebSocket 仅推送不含私有文件地址的变更通知，客户端收到通知后补拉 HTTP 数据。单实例开发使用进程内广播，生产由 Redis Pub/Sub 跨后端实例传播。

## 鉴权

访问令牌有效期 15 分钟。刷新令牌有效期 30 天，只保存 SHA-256 摘要，每次刷新都会撤销旧令牌并签发新令牌。密码修改、全端下线和账号注销会递增令牌版本，使所有旧访问令牌立即失效。WebSocket 先领取 60 秒单用途 ticket；生产环境在 Redis 中原子消费，不能重放。

## 文件与位置

图片先按文件头识别，只允许 JPEG、PNG、WebP，单文件不超过 10 MB，并使用随机对象名。封面可公开读取；相册和签到凭证只返回 5 分钟签名地址，读取时再次检查活动成员或记录归属。数据库事务回滚会删除刚上传对象，替换、删除及定时任务会回收无引用对象。本地 profile 写入本地目录；生产 profile 使用 S3 兼容存储。

位置坐标统一使用 GCJ-02。微信小程序通过后台位置监听更新，H5 仅在页面可见时轮询；移动约 20 米或最长 60 秒上报一次。地址搜索和逆地理编码由后端代理高德 Web Service。位置记录按活动和用户唯一，关闭即删除，查询只返回 90 秒内且活动未结束的数据。
