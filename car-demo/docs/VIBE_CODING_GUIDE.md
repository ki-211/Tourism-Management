# Vibe Coding 录制指引：一步步指挥 AI 做出 3D 仿真车模

> 用法：录屏时按下面的阶段推进。每个阶段都有一段**可以直接复制给 AI 的提示词**，以及**你要检查的点**。
> 本目录下现成的 demo 可以当作「目标效果参考」。录屏要展示的是**你和 AI 一起把它做出来的真实过程**，包括 AI 出错、你发现问题、引导它修好的片段。这些片段恰恰是考核的加分项。

---

## 0. 先理解考核维度，再决定录什么

| 考核维度 | 评委想看到什么 | 录屏中怎么体现 |
| --- | --- | --- |
| **AI 工具使用程度** | 你会不会用 AI 工具链，而不只是聊天 | 用 AI 编程工具（Claude Code / Cursor 等）直接改代码、跑命令、跑测试、截图验证、写文档、提交 git |
| **AI 交互协同程度** | 你是在“指挥”AI 还是被 AI 带着走 | 分阶段下需求；发截图让 AI 看问题；指出 bug 并让它定位；让 AI 先出方案你来拍板；要求它写测试自证 |
| **AI 需求理解程度** | 你能否把模糊需求变成 AI 能执行的精确需求 | 第一步让 AI 澄清需求、产出 PRD；把“高还原”“语音控车”拆成可验收的条目；验收时逐条对照 |

**一句话策略**：先让 AI 写需求文档和技术方案，然后分 6 个小步迭代，每一步都「运行 → 截图 → 反馈 → 修正」，最后让 AI 写测试和文档。

---

## 1. 录制前准备（不用录，或者只录 30 秒）

- 工具：一个 AI 编程工具（推荐 Claude Code，在终端或 VS Code 里用都可以）、VS Code、**Edge 浏览器**（用来测语音）
- 录屏：OBS Studio（免费）或系统自带录屏。建议 1080p，**分段录**，每个阶段一段，最后再剪辑
- 新建一个空文件夹，比如 `car-demo`，在里面 `git init`
- 准备一个能连上的麦克风（笔记本自带的就行）

> 💡 录屏小技巧：每段开头用一句话旁白说明「这一步我要让 AI 做什么、为什么这样拆」，评委会更容易看出你的思路。

## 2. 分阶段提示词

### 阶段 1 · 需求澄清与方案设计（体现：需求理解）⭐ 重点

**发给 AI：**

```text
我要完成一个转正作业：用 Vibe Coding 方式实现一个 3D 仿真车模 demo。
原始要求：
1. 车模高还原（参考新能源汽车中控大屏上的车模）
2. 可拖动旋转
3. 可点击控车（比如车窗）
4. 可语音控车（比如车窗）
5. 形式不限，我选择【网页】
考核维度：AI 工具使用程度、AI 交互协同程度、AI 需求理解程度。

请先不要写代码。请你：
1. 把每条要求拆成可验收的功能点（写清楚“怎样算完成”）
2. 对比 2~3 种实现方案（比如 three.js 程序化建模 vs 加载 GLB 模型；语音用浏览器 Web Speech API vs 第三方语音 SDK），说明优缺点，给出推荐
3. 列出风险点（特别是：国内网络下浏览器语音识别能不能用？麦克风权限有什么要求？）
4. 给出分阶段的开发计划
把结果写成 docs/PRD.md。
```

**你要检查：**

- AI 有没有点出「Chrome 语音识别依赖 Google 服务、国内可能不可用 → 用 Edge，加文字输入兜底」？没有的话追问：
  `国内用户用 Chrome 做语音识别会有什么问题？怎么兜底？`
- AI 有没有提到「车窗要能单独动，所以车模必须部件化」？
- **在镜头前拍板**：`采用方案 A（three.js 程序化建模 + Web Speech API + 规则 NLU），理由是……`

📦 中间产物：`docs/PRD.md`

### 阶段 2 · 搭 3D 场景，实现可拖动旋转

**发给 AI：**

```text
按 PRD 开始第一阶段：
- 纯静态网页（index.html + js 模块），用 three.js，把 three.js 下载到本地 vendor 目录（不依赖 CDN，国内网络也能离线跑）
- 深色展厅风格背景，地面加阴影和一圈发光光圈，风格参考新能源车中控大屏
- OrbitControls：拖拽旋转、滚轮缩放、阻尼，限制不能转到地面以下，空闲时缓慢自动旋转
- 先放一个简单的占位车（方块即可）
- 附带一个零依赖的 node 静态服务器 server.mjs，告诉我怎么启动
```

**你要检查：** 运行 `node server.mjs`，打开浏览器，能不能拖动？有没有报错？
有报错就**把控制台报错原文贴给 AI**（这个过程要录进去）。

### 阶段 3 · 车模「高还原」（体现：交互协同）⭐ 重点

**发给 AI：**

```text
把占位车换成一辆新能源轿车（参考 Model 3 / 小米 SU7 这类溜背轿车），要求：
- 程序化建模，不用外部模型文件。所有可控部件必须是独立的 Mesh：4 块车窗玻璃、后备箱盖、充电口盖、两个后视镜
- 车身：侧视轮廓挤出 + 圆角，俯视看车头车尾要收窄，侧面微微鼓起，带轮拱
- 玻璃舱做成黑色高光（全景天幕 + 黑化 ABC 柱），有内倾
- 细节：前后贯穿式灯带、双五辐轮毂 + 卡钳、隐藏式门把手、门缝线、后视镜
- 材质：车漆用 MeshPhysicalMaterial（clearcoat），加环境贴图反射，ACES 色调映射，灯带加 Bloom 发光
```

**接下来是最关键的「迭代」环节，一定要录：**

1. 截图发给 AI，具体指出问题。示例：
   ```text
   （附截图）问题：1）车头太方太高，像面包车；2）侧面有一条明显折痕和斜向的明暗块；
   3）地面太亮，车不突出。请分析原因再改。
   ```
2. 关注 AI 的分析是否到位。例如折痕的真正原因是 ExtrudeGeometry 的侧面只有几个大三角形，做非线性变形后会出现折面，需要细分网格（本 demo 最后用了 Delaunay 细分）。**能追问原因而不是只说“再改改”，就是协同能力的体现。**
3. 再提一轮细节要求：`门缝线、灯带要贴合车身曲面，不要悬空`。可以引导 AI 用「射线投射到车身表面」的方法来放置装饰件。

> 🎯 如果你更追求「照片级还原」，可以走方案 B：在 Sketchfab 下载免费 GLB 车模（注意许可证），让 AI 写代码按网格名称找到车窗、车门，再做动画。这条路要用 Blender 把车窗拆成独立网格，工作量更大。可以在 PRD 里说明你为什么没选它。

### 阶段 4 · 点击控车

**发给 AI：**

```text
实现点击 3D 模型控车：
- 用 Raycaster 拾取。点车窗：升降切换；点灯带：开关大灯；点后备箱盖：开合；点充电口：开合（打开时内圈发绿光）；点后视镜：折叠/展开
- 车窗升降要真实：玻璃向下平移，用 clippingPlanes 在腰线以下裁掉，看起来像降进车门。动画要平滑（约 2.5 秒走完全程）
- 区分“拖拽”和“点击”：鼠标位移超过 6px 视为拖拽，不触发控车
- 悬停时鼠标变手型，并显示提示“主驾车窗 · 点击打开”，车窗有淡蓝色高亮
- 车窗全开后，玻璃已经看不见了，点窗框里的空洞也要能关上（提示：用不可见的点击热区）
- 车里放头枕、方向盘，开窗后能看到车内
```

**你要检查：** 快速连点、边拖边点、车窗半开时点击，行为是否合理。发现 bug 就**描述复现步骤**给 AI。

### 阶段 5 · 中控风格 UI 面板

**发给 AI：**

```text
参考新能源车中控大屏做 UI：
- 顶栏：品牌名、电量续航、温度、锁车状态、时间
- 左侧玻璃拟态面板：4 个车窗的开度滑杆 + 全开/透气/全关；快捷开关（大灯、后备箱、充电口、后视镜、车锁、氛围灯）；氛围灯颜色和车漆色板
- 右侧：视角切换（车头/车尾/左侧/右侧/俯视）+ 自动旋转开关，视角切换要有平滑过渡
- 所有入口（点击模型、面板、语音）都调用同一套车控 API，状态单一数据源，UI 自动同步
- 手机竖屏也要能用：面板可折叠，车不能被裁掉
```

> 💡 “单一数据源”这句话是在展示你的架构判断，可以在旁白里解释：这样做语音控车时只需要多接一个入口。

### 阶段 6 · 语音控车（体现：需求理解 + 工具使用）⭐ 重点

先理解原理（可以在视频里用 30 秒讲清楚）：

```
说话 ─► ① 语音识别 ASR ─► 文字“把主驾车窗开一半”
        ─► ② 语义理解 NLU ─► {type:'window', targets:['fl'], value:0.5}
        ─► ③ 执行 ─► car.setWindow('fl', 0.5) ─► 3D 动画
        ─► ④ 语音播报 TTS ─► “主驾车窗已调整到 50% 开度”
```

- ① 和 ④ 浏览器自带（`SpeechRecognition` / `speechSynthesis`），不用申请 Key
- ② 是体现“需求理解”的地方，**不要只做关键词匹配**

**发给 AI：**

```text
实现语音控车，分四层：ASR → NLU → 执行 → TTS。
1. ASR：用 Web Speech API（webkitSpeechRecognition），zh-CN，显示实时识别结果；处理好各种错误（无权限、network 错误要提示换 Edge 浏览器）；点麦克风或按空格键开始
2. NLU 单独写成纯函数模块 nlu.js（方便测试），支持：
   - 车窗位置：主驾/副驾/左后/右后/前排/后排/全部（注意“副驾驶”里也包含“驾驶”两个字）
   - 开度：一半、百分之三十、40%、开条缝
   - 动作同义词：打开/降下/摇下 vs 关闭/升起/摇上
   - 多意图：“打开大灯然后打开后备箱”
   - 隐式意图：“车里有点闷”→开窗通风，“下雨了”→关窗
   - 上下文：“打开副驾车窗一半”之后说“再开大一点”
   - 其他：大灯、后备箱、充电口、锁车/解锁（“解锁”包含“锁”字要先判断）、后视镜、氛围灯颜色、车漆、视角
   - 听不懂时给友好提示
3. 执行后用 speechSynthesis 播报中文回复，并用对话气泡展示
4. 必须有文字输入框兜底，和语音走同一条链路；再放几个示例指令按钮
5. 先写 NLU 的单元测试（node 直接跑），再写实现，跑通所有测试
```

**你要检查（务必录下来）：**

- 用 **Edge** 打开，真的对着麦克风说「打开主驾车窗」「后排车窗开一半」「车里有点闷」
- 在终端里跑 `node tests/nlu.test.mjs`，展示测试全部通过
- 故意说一句它听不懂的话，展示兜底回复
- 如果某句话解析错了（比如“关闭副驾驶车窗”把主驾也关了），**把错误现象告诉 AI，让它先补一个测试用例再修**。这是很好的协同片段

> 🚀 进阶加分（可选）：让 AI 把 NLU 换成「大模型 + Function Calling」。把车控 API 定义成 tools，让大模型输出结构化指令，规则 NLU 作为离线兜底。需要 API Key，注意别把 Key 写进前端代码，录屏时也别露出来。

## 4. 两分钟演示脚本（最终成果展示）

1. **（0:00）** 打开页面，车模自动旋转。用鼠标拖动 360° 查看，滚轮缩放，切换「车头 / 车尾 / 俯视」
2. **（0:30）** 点击车模上的主驾车窗 → 降下；再点 → 升起；点后备箱、充电口（绿光）、后视镜
3. **（0:50）** 面板拖动右后车窗滑杆到 30%，换车漆颜色
4. **（1:05）** 按空格说话：
   - 「打开主驾车窗」
   - 「后排车窗开一半」
   - 「再开大一点」（上下文）
   - 「车里有点闷」（隐式意图）
   - 「打开大灯然后打开后备箱」（多意图）
   - 「氛围灯换成紫色」
   - 「锁车」（车窗自动关闭、后视镜折叠、闪灯鸣笛）
5. **（1:50）** 一句话总结架构：ASR → NLU → 车控 API → 3D 动画 / TTS；三种控车入口共用同一套状态

## 5. 常见坑

| 现象 | 原因 / 解决 |
| --- | --- |
| 双击 index.html 白屏 | ES Module 不能在 `file://` 下加载，要用 `node server.mjs` 启动 |
| 点麦克风提示 network 错误 | 在用 Chrome，而 Chrome 识别依赖 Google 服务。换 Edge，或用文字输入 |
| 麦克风权限没有弹窗 | 必须在 `localhost` 或 `https` 下打开；在地址栏左侧手动允许麦克风 |
| 没有语音播报 | 系统缺少中文语音包（Windows：设置 → 时间和语言 → 语音，添加中文） |
| 手机上打不开麦克风 | 手机访问局域网 IP 用的是 http，没有麦克风权限。要部署成 https 链接 |
